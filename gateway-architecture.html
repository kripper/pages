OpenHands V1 Gateway Architecture

How Agent Canvas connects to self-hosted OpenHands through the app-server proxy

OpenHands#14909 - Backend (V1 Gateway) agent-canvas#1435 - Frontend

Overview

The V1 Gateway enables Agent Canvas (the web UI) to connect to self-hosted OpenHands through the app-server as a single unified endpoint. Instead of the browser connecting directly to sandbox agent-servers (which may not be reachable), all traffic flows through the app-server, which acts as a transparent proxy.

Two PRs, one feature: OpenHands#14909 adds the gateway backend; agent-canvas#1435 makes the UI gateway-aware. Both must be deployed together.

Request Flow: Direct vs. Gateway

Direct Mode (default)

graph LR
    B["Browser"] --> |"REST + WS"| S["agent-server in Sandbox"]

Browser connects directly to the sandbox agent-server using the conversation_url returned by the backend.

Gateway Mode self-hosted

graph LR
    B["Browser"] --> |"All traffic"| G["App-Server Gateway"]
    G --> |"Proxied"| S["agent-server in Sandbox"]

Browser connects only to the app-server. The gateway proxies both WebSocket and REST to the sandbox. Enabled by ENABLE_WEBSOCKET_GATEWAY=true.

askAgent Routing Decision

flowchart TD
    Start[askAgent called] --> Fetch[Fetch conversation data]
    Fetch --> Check{websocket_url present?}
    Check -->|Yes| GW[Route through App-Server POST /api/conversations/id/ask_agent]
    Check -->|No| DX[Direct call to agent-server sandbox]
    GW --> End[Response returned]

Key insight: shouldUseGateway() simply checks whether websocket_url exists on the AppConversation. When present, all HTTP and WebSocket traffic is routed through the app-server proxy instead of connecting directly to the sandbox.

Cloud Proxy Compatibility

The cloud_proxy router was removed from SDK v1.29.0

software-agent-sdk#3326 by @hieptl removed the agent-server POST /api/cloud-proxy route.

Why this PR is NOT blocked:

  • callCloudProxy() only posts to the local/bundled agent-server /api/cloud-proxy when hostOverride or forceProxy is set
  • The askAgent call in this PR sets neither -- it is a direct browser request to ${activeBackend.host}/api/conversations/{id}/ask_agent
  • OpenHands#14909 implements POST /{id}/ask_agent on the app-server side as a proxy with 600s timeout
  • The websocket_url path is also independent of SDK /api/cloud-proxy: #14909 returns a relative /ws/events/{id} when ENABLE_WEBSOCKET_GATEWAY is enabled, and this PR resolves that against the active backend host
Important caveat: Other pre-existing Agent Canvas cloud/runtime paths still use callCloudProxy(... hostOverride: ...), which does require the local/bundled agent-server /api/cloud-proxy route. Those would need a separate migration before we can safely bump Agent Canvas bundled agent-server to v1.29.0+.

Current pin: openhands-agent-server==1.22.1 / openhands-sdk==1.22.1

How to Enable

On the OpenHands Backend

Set ENABLE_WEBSOCKET_GATEWAY=true on the app-server.

Optionally, if sandboxes are not reachable by the app-server by default: SANDBOX_CONTAINER_URL_PATTERN="http://127.0.0.1:{port}"

On Agent Canvas

Add your self-hosted OpenHands instance as a backend. The UI auto-detects the gateway mode via websocket_url in the conversation response.

Set VITE_ENABLE_WEBSOCKET_GATEWAY="true" in frontend/.env and rebuild if using the bundled frontend.
